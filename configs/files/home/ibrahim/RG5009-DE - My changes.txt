Yes. The usual and recommended setup is:

MikroTik → RADIUS → Windows NPS → Active Directory Domain Services

MikroTik generally should not authenticate directly against AD DS. Install and configure Network Policy Server (NPS) on Windows Server, join NPS to the domain, and let NPS validate users against AD.

1. Configure Windows Server
On the Windows Server:

Install the Network Policy Server role.
Register NPS in Active Directory:
Open NPS
Right-click NPS (Local)
Select Register server in Active Directory
Add the MikroTik as a RADIUS Client:
Friendly name: MikroTik
Address: 10.1.0.253 or the MikroTik source address used for RADIUS
Shared secret: create a strong secret
Create a Network Policy allowing the required AD users or groups.
Allow the required authentication method, commonly PAP for MikroTik administrative login or MS-CHAPv2 for supported VPN/PPP scenarios.
Allow UDP ports 1812 for authentication and 1813 for accounting through the Windows Firewall.
NPS uses AD users and groups for authorization, so you can create a group such as MikroTik-Admins and permit only that group.

2. Add the NPS server to MikroTik
Assuming your Windows NPS server is 10.1.0.254:

routeros


/radius
add address=10.1.0.254 \
    secret="CHANGE_THIS_TO_THE_SAME_NPS_SECRET" \
    service=login \
    authentication-port=1812 \
    accounting-port=1813 \
    protocol=udp \
    comment="Windows NPS / Active Directory"
Enable RADIUS authentication for MikroTik administrator logins:

routeros


/user aaa
set use-radius=yes accounting=yes
You can test with WinBox, WebFig, SSH, or the terminal using a domain account.

Use either:

text


username
or:

text


DOMAIN\username
depending on how the NPS policy is configured.

3. Optional: use RADIUS for VPN, hotspot, or Wi-Fi
For PPP/VPN authentication:

routeros


/ppp aaa
set use-radius=yes accounting=yes
For HotSpot:

routeros


/ip hotspot profile
set [find] use-radius=yes
For wireless WPA-Enterprise, configure the relevant security profile to use RADIUS and create an NPS policy for the wireless authentication method.

Important security recommendations
Keep at least one local MikroTik administrator account as a recovery account:

routeros


/user
add name=local-admin group=full password="USE_A_LONG_UNIQUE_PASSWORD"
Do not remove local authentication until RADIUS has been tested successfully. Also restrict RADIUS access in the Windows Firewall so only the MikroTik can send requests to UDP ports 1812 and 1813.

The RADIUS shared secret must match exactly on both MikroTik and NPS. MikroTik supports RADIUS for services such as router login, PPP/VPN, HotSpot, and wireless authentication.
